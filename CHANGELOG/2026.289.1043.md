# 2026.289.1043 — docs(skill): point the crabbox-deploy cross-reference at `crabbox-cli` (producer sweep for marketplace#469)

## Summary

Sweeps the one live cross-reference to a skill that has been renamed: `opencharly/layer-crabbox` renamed its projected skill from `crabbox` to **`crabbox-cli`**, so `/charly-tools:crabbox` no longer resolves.

**Why the rename happened.** Two opencharly repos declared one skill name — `layer-crabbox` (family tools, the CLI candy) and `plugin-crabbox` (its `crabbox:` check verb). The marketplace corpus carries both, which is survivable; the umbrella's **derived** harness binding (`AGENTS.md` Part II #5) is not, because it is a flat farm of entries named after the skill and *"a flat farm cannot bind both"*. Its re-derivation step now fails outright, and that failure lands on the **umbrella pin advance** — so one duplicate skill name is holding a whole cross-repo pin wave (`opencharly/marketplace#469`). `plugin-crabbox` keeps `crabbox`; the CLI candy takes `crabbox-cli`.

**Swept here:** `.agents/skills/crabbox-deploy/SKILL.md:79`, in its Cross-References section. This is **authored** content, not a marketplace projection — the marketplace's `automation/skills/crabbox-deploy/SKILL.md` is generated from this file, so the fix belongs here and the projection follows on regeneration. A stale `/charly-<family>:<skill>` reference is a hard error in the docs build, so this rides **producer-first**.
