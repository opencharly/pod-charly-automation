# 2026.260.1952 — feat(automation): add triggers: to the agent + alias skills

## Summary of changes

The R0 dispatcher regeneration (`marketplace/DISPATCHER.md`, emitted by
`charly marketplace generate` from each skill entity's `triggers:`) needs every skill entity
that should route from the R0 table to carry `triggers:`. This PR adds `triggers:` to EVERY
`type: skill` entity in this repo's `charly-automation` candy that lacked one — the class the
first revision only partially covered — and fixes the red `build` required check at its root.

- `charly.yml` — `triggers:` added to **8** `type: skill` entities: `agent`, `alias`, `enc`,
  `openclaw-deploy`, `sidecar`, `tmux`, `udev`, `crabbox-deploy`. (`agent-control-operator` is
  `type: agent` and is correctly EXEMPT: the emitter skips agents — they are dispatch targets,
  not dispatch sources.) No `type: skill` automation entity is left without `triggers:`.
- `.github/workflows/deploy.yml` — the pinned charly clone tag
  `v2026.238.1242` → `v2026.247.1701`.

**RCA — the red `build` (R1).** The `build` required check has been red since 2026-09-04: the
workflow pins charly `v2026.238.1242`, whose schema is `2026.232.0520`, while `charly.yml`
declares schema `2026.240.1943`, so every run failed with *"config schema 2026.240.1943 is newer
than this charly supports (max 2026.232.0520)"*. `v2026.247.1701` is the newest charly tag whose
pinned `spec` (`v0.2026245.1613`) carries `#SchemaVersion: 2026.240.1943` exactly; the next tag
(`v2026.248.1547`) raises the schema to `2026.248.1030`.

**R2 — the whole class is completed in this tree (no parking).** An earlier revision added only
the two umbrella-row skills and disposed of the other six as "out of scope". That was the
forbidden R2 split (and the validator blocked it, correctly): the PR had established that a
missing `triggers:` means no dispatcher row, then left six more instances unfixed. All eight
`type: skill` entities now carry `triggers:`.
